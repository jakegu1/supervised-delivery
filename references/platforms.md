# Platform adapters

Use the adapter for the surface actually available. Inspect the host's tools or installed CLI help before relying on a flag or API. Each session record needs its provider, concrete ID or URL, workspace, baseline, and current action. A credential enables access. Authorization to send code or data, start billed work, change settings, merge, or release comes from the user and applicable rules.

## Capability matrix

Official documentation checked 2026-11-11. Features vary by surface, version, organization, and installed configuration. The matrix describes documented capabilities. The checks below cover documentation, tool schemas, or help output. Live cross-platform execution remains unverified.

| Platform | Skill or rule loading | Dispatch, resume, and status | Isolation and non-interactive operation | Evidence and limits |
|---|---|---|---|---|
| Codex | `SKILL.md`; documented `.agents/skills/` roots | Desktop chats and subagents where exposed; CLI or app-server thread identities | Managed worktrees when available; `codex exec` with JSON events | CLI help and desktop tool schemas inspected. Live run unverified. |
| Cursor | `.cursor/skills/`; local compatibility roots; `.cursor/rules/` for project rules | Agent chats or CLI thread IDs; Cloud Agents have a separate lifecycle | Worktree mode, cloud VM, and headless CLI | Official documentation only. Live run unverified. |
| Devin | Devin CLI `.devin/skills/` or `.agents/skills/`; project rules | CLI session IDs, subagent panel, Cloud session IDs/URLs | Local checkout under the chosen sandbox or Cloud VM; print mode | Official documentation only. Live run unverified. |
| DeepSeek Harness | Official `dsh` skill providers, including `.dsh/skills/` and `.agents/skills/` | Persisted Harness session IDs, optional composed subagent tools, headless event stream | Isolated checkout; optional worktree bundle; headless profile | In one checked `dsh 0.1.0-rc.6` installation, headless help omitted `--json` and `--session-id`. ### Codex

- **Load.** Use `$supervised-delivery` in a host that supports skill invocation. For portable repository use, put the folder under `.agents/skills/`. Confirm discovery in the target client, especially when copying across versions. [Build skills](https://learn.chatgpt.com/docs/build-skills)
- **Coordinate.** Discover the tools exposed in the current chat. Where these desktop tools are exposed, `list_threads` identifies existing chats. `send_message_to_thread` requires the human's explicit authorization for that target. Use `create_thread` only when the human explicitly asks for a separate chat. Use authorized subagent tools for work under the same chat. A queued creation can return a client ID before it has a usable thread ID. Wait for a real thread and host ID. Use `wait_threads` with the last cursor for compact observation, and fetch history only to resolve a concrete discrepancy. These are desktop tool contracts, so read the active schema. The standalone app-server exposes its own `thread/start`, `thread/resume`, and turn events for clients already using that protocol. [Codex App Server](https://learn.chatgpt.com/docs/app-server)
- **Execute.** Use an attached eligible worktree or a managed worktree tool when supported. A clean checkout from a ref excludes unrelated uncommitted changes. The CLI supports `codex exec --json` for structured output and `codex exec resume <SESSION_ID>` for a known previous run. Use the recorded checkout and retain the event log. [Git worktrees](https://learn.chatgpt.com/docs/environments/git-worktrees) · [Non-interactive mode](https://learn.chatgpt.com/docs/non-interactive-mode)

### Cursor

- **Load.** Put the folder in a supported project or user skills root such as `.cursor/skills/` or `~/.cursor/skills/`. Local Cursor documents compatibility with Codex skill directories. Keep always-on project rules in the project's rule mechanism. Cloud workers need the skill in their accessible project or an already-authorized sync/setup. A local folder alone does not make it available remotely. [Skills](https://cursor.com/help/customization/skills) · [Agent in CLI](https://cursor.com/docs/cli/using)
- **Coordinate.** Use a selected Agent chat, or the documented CLI `agent ls` and `--resume <thread-id>` for an existing local conversation. Use the active workspace and recorded thread. Authorized Cloud Agents have their own IDs and status. The Cloud Agents API documents launch, status, follow-up, and run streaming. Use it only if the actual integration, remote repository access, and spending are authorized. [Agent in CLI](https://cursor.com/docs/cli/using) · [Cloud Agents API](https://cursor.com/docs/cloud-agent/api/endpoints)
- **Execute.** Cursor supports isolated worktrees in the editor and CLI `--worktree` mode. Verify the checked-out base and read the project's setup rules before creating a new worktree. Headless CLI supports `-p` and `--output-format stream-json`. Keep current workspace trust and approvals. Cloud Agents run in separate VMs with repository and network access, so review what scope is sent there. [Worktrees](https://cursor.com/docs/configuration/worktrees) · [Headless CLI](https://cursor.com/docs/cli/headless) · [Cloud Agents](https://cursor.com/docs/cloud-agent)

### Devin

- **Load.** Devin CLI documents project skills under `.devin/skills/` and `.agents/skills/`, slash invocation, and automatic selection. Keep applicable project rules in their existing location. CLI skill discovery establishes local support. Confirm availability in the Cloud session or include the packet and necessary references in authorized context. [Skills overview](https://docs.devin.ai/cli/extensibility/skills/overview) · [Rules and AGENTS.md](https://docs.devin.ai/cli/extensibility/rules)
- **Coordinate.** Devin CLI can resume a specific local session with `devin --resume <SESSION_ID>`. The documented subagent panel shows status for delegated local work. For an already-authorized Devin Cloud session, use the session's ID or URL and the Cloud UI or documented `devin --cloud -r <ID-or-URL>` to resume and steer. Reuse that identity when work is paused or a local observer exits. [CLI commands](https://docs.devin.ai/cli/reference/commands) · [Subagents](https://docs.devin.ai/cli/subagents) · [Cloud in the CLI](https://docs.devin.ai/cli/cloud)
- **Execute.** Start local work from the agreed isolated checkout and use the installed sandbox and permissions. Cloud sessions run in their own VM with repository clones. Confirm the actual branch and base. `devin -p` is local print mode and `devin --cloud -p` sends one prompt to a Cloud session and exits. Track the Cloud session separately. Use a supported approved workspace when headless mode cannot ask for trust or permissions. [CLI commands](https://docs.devin.ai/cli/reference/commands) · [Sandbox](https://docs.devin.ai/cli/sandbox) · [Cloud in the CLI](https://docs.devin.ai/cli/cloud)

### Official DeepSeek Harness

- **Load.** This adapter targets `deepseek-ai/deepseek-harness` and the `@deepseek-ai/dsh` launcher. When mounted, the filesystem provider reads project `.dsh/skills/`, `.agents/skills/`, and configured user roots. The skill tool loads the catalog based on the session's working directory. Use `/supervised-delivery` where the loaded profile supports explicit invocation. If discovery is incomplete, attach or point to the skill folder explicitly. [Official repository](https://github.com/deepseek-ai/deepseek-harness) · [Filesystem discovery](https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/skill/skill-filesystem/README.md) · [Skill tool](https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/skill/tool-skill/README.md)
- **Coordinate.** Use a selected workspace in Web or another installed profile. Use native subagent tools only if the current composition exposes them and the caller is authorized. The upstream headless documentation describes a single persisted task via `dsh --profile headless`, `--json` events with a session ID and final reason, and `--session-id <id>` to resume an eligible session in the same workspace after the previous process exits. In one checked `dsh 0.1.0-rc.6` installation, headless help omitted both flags. Runtime behavior for those flags is unverified. Verify the installed profile before relying on either flag. When the capability is unavailable or unverified, use the complete [packet and handoff templates](milestone-packet.md) through an available authorized route. A tool result or process exit alone does not verify the packet. [Web user guide](https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/user/guide/index.md) · [CLI help](https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/cli-help.md) · [Headless semantics](https://github.com/deepseek-ai/deepseek-harness/blob/fcc0ad462172522aaf5c93a7b2e01f6b9f0b0159/packages/bundle/headless/README.md) · [Tool catalog](https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/tool-catalog.md)
- **Execute.** Run from the agreed isolated checkout. The official optional worktree bundle can create and enter a separate checkout when mounted and permitted. A new session alone does not isolate files. Headless is one task per invocation with no interactive follow-up. Preserve the run log and respect the mounted permission profile. [Worktree bundle](https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/experimental/worktree/README.md) · [Headless profile](https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/bundle/headless/README.md)

## File and prompt fallback

If skill discovery, routing, or session tracking is absent or unverified, use the [packet and handoff templates](milestone-packet.md). Bundle the skill, relevant references, frozen packet, base ref, and evidence pointers for the target. If you can start or resume the target using an authorized local channel, deliver the packet directly. If only the human can open the target, provide one paste-ready dispatch and a compact return format. Preserve the resulting candidate ID or digest and use the same independent review gate. State which platform actions were actually performed.
